# 小组 HTML 原型审查与评审清单

2026-09-26。新版：[group-system-review.html](../demos/group-system-review.html)。仅本机演示，不调用真实 API、不发送邀请、不上传数据。

## 最新更新：状态回归 —— 待审批回访与列表加载/失败（v10）

PRD 验收要求"加载中/请求失败/未登录不得伪装成空状态"，而原型只有成功态与离线态；申请待审批后回到空状态也只看到"还没有小组"，用户会以为申请丢了。本轮补两处。

评审工具"网络与访问状态"新增**请求加载中**与**请求失败**两项。"我的小组"列表页据此渲染：加载页为提示条 + 占位卡片，创建/加入按钮均禁用；失败页明确"这不等于你没有小组"，提供重试与稍后再说，并在页下说明离线有缓存时应改为展示缓存列表。同一状态下小组详情/活动页顶部出现对应提示条（"正在同步小组数据…" / "同步失败 · 当前显示本机缓存，写操作暂不可用"），避免切了状态却看不到变化。

待审批回访：`s.joinVisitorState==='pending'` 时，首页横条摘要变为"加入申请待审批 · 组名"；"我的小组"（含空状态）顶部出现待审批卡片，写明组名、小组号与"管理员同意后自动进入小组"，并提供"刷新审批状态"和"撤回申请"。撤回沿用既有 `withdraw`，补上结果提示；离线时两个按钮禁用，与写操作口径一致。右侧评审清单加了两条对应检查项。

浏览器实测（结构化断言，非人工目检）：加载页文案命中、创建按钮 `disabled=true`；失败页命中且点击重试后 `s.network==='online'` 并回到正常列表；详情页命中缓存提示条；空状态 → 加入 → 查找 `82603158` → 申请加入后 `joinVisitorState==='pending'`，回空状态命中待审批卡片，刷新提示"仍在等待审批"，撤回后 `joinVisitorState==='none'` 且卡片消失，首页横条显示"加入申请待审批 · 周六羽毛球"。撤回后进"加入小组"回到预览卡片并可再次"申请加入"，不是死胡同。控制台无报错。评审帧（设备宽 470）下待审批卡片使内容区纵向多出 140px，`.content` 是可滚动容器，按钮仍可达；横向无溢出。**390×844 手机帧未在本轮复测**，评审时请顺手确认整屏版式。

边界：加载/失败只覆盖"我的小组"列表与详情页顶部提示条；**小组号查找结果页和结果详情页的加载/失败态仍未画**，原生实现按 PRD §7 状态矩阵逐页补齐。刷新按钮只是提示"仍在等待审批"，原型没有管理员批准访客申请的通路（成员页的审批针对另外的人）。

## 前次更新：项目目录化（v9）

原型此前把"羽毛球"写死在 6 处标签与 2 处比分校验里，与首批扩为四个项目的结论冲突。本轮引入 `SPORTS` 目录（羽毛球/乒乓球/网球/匹克球），小组号卡片、项目徽标、加入预览、活动详情、战绩赛制筛选、创建项目选择器全部按 `s.sport` 派生。

补记与快速计分的每局合法性改为规则驱动：羽毛球 21 分/30 封顶、乒乓球 11 分、匹克球 11 分/15 封顶、网球按 6/7 局判定（简化），术语随项目切换为"局/得分"或"盘/局分"。这落实了设计文档"不能把 demo 的 21 分封顶固化到所有项目"的要求。

浏览器实测：新建网球组后，概览徽标显示"网球 · 项目固定"，战绩筛选为"网球单打/网球双打"，补记填 6:4、3:6、7:5 通过、填 21:18 被拦截并给出网球示例；匹克球 11:6 与 15:13 通过；羽毛球原 21:18、17:21、21:19 回归通过。

同轮修掉两个真实缺陷：(1) 快速计分演示的默认比分恒为 21:17，非羽毛球项目会直接校验失败，改为按项目预填；(2) 新建组只有组主 1 人，"立即计分/补记"要求 2 人以上却无任何引导，现给出"邀请朋友或添加临时成员"的提示。另修正一处自伤：为兼容旧调用点新增的 `validSetPoints` 两参数包装函数覆盖了新实现，导致无限递归栈溢出，已删除包装并统一为三参数调用。

## 前次更新：小组简介（v8）

创建表单新增选填简介（≤200 字，含超长拦截）；小组概览展示简介，超两行截断并提供"展开全文/收起"，组主/管理员可就地编辑或清空，无简介时显示"添加小组简介"；按小组号查找到的预览卡片同样显示两行简介。普通成员只读，编辑入口消失。

结论：首版**不做组公告**，只做简介；临时通知留在活动详情。设计文档已补权限行与匿名预览返回字段。

## 前次更新：小组空状态引导（v7）

新增完整空状态：小组图标、“还没有小组”标题、两行介绍、约活动/记比赛/看战绩三条说明，下方为创建/加入入口并提示小组号或扫码。演示导航新增“小组空状态”，产品页移除“体验无小组状态”调试按钮。空状态只介绍一期基础能力，保留当前原生风格与深浅色。

浏览器实测：创建入口打开仅两种加入方式的创建表单；加入入口出现小组号输入与“扫一扫”。390×844 视口无横向溢出，内容区 clientHeight/scrollHeight 均为 659，整页内容及按钮可容纳于模拟手机内；深色文本与按钮可见。加载失败/未登录/待审批的原生状态分流已写入设计文档，HTML 本轮未补齐全部状态。（其中"加载失败"和"待审批回访"已在 v10 补齐，见本节开头；未登录态仍只有加入页的登录勾选模拟。）

## 前次更新：创建时不可关闭加入（v6）

按用户反馈，创建表单移除“关闭加入”，只保留直接加入/需要审批；创建后设置仍可关闭和重新开放，并明确不影响已有成员。创建者自动为组主，成功引导改为邀请朋友，不再优先提示添加临时成员。技术设计同步限制创建 API 的枚举，拒绝 CLOSED；更新 API 才接受三种方式。

## 前次更新：补记整场局分与可选逐局比分（v5）

补记改为先填整场局分，选填展开的每局小分；支持只保存 2:1，也支持保存 21:18、17:21、21:19 明细。列表主比分标注“局分”，详情展示局制及明细完整性。正常计分演示仍是现有单局替身，未改原生计分代码。

## 前次更新：小组号与二维码双入口（v4）

用户明确保留两种方式：输入小组号加入、扫码加入；分享对应复制号码、分享二维码。加入页已有“扫一扫”，小组“邀请朋友”提供两种分享选择，二维码页能保存实际编码图片并预览识别结果。相机/相册识别采用清楚标明的模拟按钮，不请求权限、不发送外部分享。

二维码由本机已有 qrcode 库生成，编码示例数字号码，非装饰图；正式二维码将编码同一 groupNo 的 HTTPS 加入链接，具体承接见设计文档。当前纯数字示例码不代表已上线 App/微信跨端能力。

## 前次更新：固定数字小组号（v3）

用户提出用纯数字小组号简化加入，已采用。普通加入移除临时邀请码、有效期、使用次数及撤销操作。输入号码查找后再加入；登录只在必要时出现。加入方式已在 v6 区分为创建时两种、创建后设置三种，成员可复制公开号码，详情显示固定小组号。

示例号 `82603158`；新建演示组 `82603159`。数字长度建议 8 位，默认审批是本稿建议。临时成员认领仍独立核对，不能仅凭组号占有历史。

## 2. 新版可操作范围

- 首页：横向“我的小组”条目紧挨现有“我的球局”之前，进入小组列表；演示无小组空态。
- 创建：名称校验、固定羽毛球项目、创建后进入详情。创建会切换到新小组演示数据，可重置恢复原示例。
- 按号加入：输入 `82603158` 查找、展示最小资料、按组设置直接加入或申请。未登录才走登录，已登录直接继续；不存在/满员/关闭/归档/已加入有对应状态。
- 分享/设置：所有账号成员可复制小组号或查看/保存二维码，加入页支持模拟相机/相册识别；创建时只可选直接加入或需要审批，组主之后在设置可关闭加入；改变方式不改号。
- 小组：概览/活动/战绩/成员四页签，角色控制按钮。
- 约球：编辑时间地点容量、报名/退出报名、选取实际对阵、取消二次确认。
- 成绩：2/4 人席位选择、正常计分单局校验、补记日期/整场局分/可选逐局校验、待同步/待确认/冲突/已确认/作废；确认与作废影响战绩。
- 成员：审批申请、添加临时球友、本人认领 → 管理员核对、移除普通成员、转让所有权、退出、归档/恢复。
- 轮转：1–3 块场地、候场人数、完成后下一轮、离线/角色门槛。
- 联赛：待确认结果确认后更新独立赛季榜。
- 适配：手机宽度、桌面评审布局、深浅色、键盘焦点、Escape 关闭弹层、表单校验提示。

## 3. 明确演示边界

- 刷新恢复初始数据；没有真实数据库、JWT、自动重试、幂等接口、并发控制或跨端联网。按钮文案的“同步/确认”都是本页模拟。
- 网络与角色下拉框是评审工具；用于独立切换情景，不是真实账号切换流程。按号加入页可独立模拟外部访客，初始所有者数据不代表访客自动拥有成员权限。
- 首页其他区域是上下文示意，原生实施必须沿用现有布局；本轮只有新增横条的位置与层级已确定。
- 创建以单组演示数据替换当前示例，不是完整多组管理实现。创建后展示无活动引导，约球表单提供可编辑示例初值，保存前不生成活动。
- 正常计分页仍是单局结束结果的交互替身。补记页面已独立为整场局分 + 可选逐局，明细仅演示 21 分制校验；正式项目规则、局比分、胜者推导见技术设计。不重做原生计分板。
- 普通约球采用“一活动一场结果”的评审建议；多场/多人持续轮转另评审。
- 临时认领演示未成为成员的账号直接认领；已是成员时的合并、同场双边身份冲突在技术文档中定义，HTML 未完整模拟。
- 修正结果的版本审核、精确错误码、加载/超时、可恢复编辑冲突、账号注销、举报、通知设置、解散冷静期只在设计文档定义，HTML 尚未逐屏实现。
- 作废与冲突核对使用演示快捷动作；正式 UI 必须收集原因、保存审计，不能直接复用本页事件处理器。
- 轮转为固定演示排阵，不是生产公平算法；联赛使用独立样例，不向一期榜单写入，避免误把未开发能力当成可用闭环。
- 示例日期固定为 2026-09-26 基准，实际功能以服务端时间判断截止/有效期。
- 首页非小组的旧功能用静态上下文表达，不能点击；二维码是真实数字示例，扫码为模拟识别，不提供生产邀请链接或自动发送分享。
