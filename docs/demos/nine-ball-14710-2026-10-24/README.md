# 九球追分 14710 交互 Demo

打开 `index.html` 即可交互，无外部依赖，也不连接线上账号。

- 手机和鸿蒙手表预览共用同一场示例；支持 2/3/4 人。
- 手机布局按当前 iOS 记分板结构调整：无占位顶栏／底栏，姓名顶部固定、比分独立居中，返回／编辑／菜单悬浮。
- 按本轮最终选择，开球人使用姓名左侧球杆图标，不展示文字 Chip。图标与姓名作为一组居中，每人预留同样的图标位，切换开球人不移动姓名或比分。图标完整复用 `jifen/Assets.xcassets/ic_snooker_cue.imageset/ic_snooker_cue.svg` 的两条路径。
- 首次提示说明当前局数与开球人，并区分「本局开球人」与「当前击球人」；弹窗只有「知道了」按钮，不显示右上角叉。本地浏览器记住已显示状态，换局、重置示例、切换设备及刷新都不再自动弹出；页外按钮可手动重播。
- 提供 3～4 字姓名预览。圆表姓名行根据圆形安全区约束可用宽度，保持左侧图标完整；极窄窗口长姓名可省略，玩家按钮的无障碍名称和记分弹窗仍显示全名。
- 每人底部 3 列 × 2 行分项次数统计，旧「自由球」位置改为本次规则中的「让杆」。短色块压缩统计格高度，避免遮挡比分。
- 普胜、犯规前置；大金、小金、黄金9在第二排；让杆独立且不计分。
- 双人六项操作均直接记录，不再弹出第二层确认：普胜±4、小金±7、大金±10、黄金9±4；犯规向对手转1分；让杆不计分。所有操作仍可整笔撤销。赢局自动换局并按约定更新开球人。
- 操作弹窗仅保留玩家姓名、事件和分值；让杆使用有填充背景的独立按钮。确认弹窗仅显示付分人、分数变化及下一局开球人，完整说明放在菜单的「本场规则」。
- 双人让杆直接记录唯一对手，不再经过选人／确认层；多人保留继续击球人选择。两种操作均不计分、不换局，并可整笔撤销。
- 犯规一击完成双方转分，按钮固定显示「本人 −1／对手 +1」（双人）或「本人 −1／下家 +1」（多人），不把真实姓名塞入按钮；提示和明细保留姓名。两段分数文案各自不拆行，小屏允许整段换行。
- 小金默认本局开球人付分；多人确认页可更正开球人，也可在开局设置选择全员付分模式。双人不弹确认，当前内核判为无效的小金按钮置灰，并可从上方更正开球人。
- 两人普胜直接记分：赢家+4、唯一对手−4，自动进入下一局，可整笔撤销。多人普胜预选座位上家，可确认实际付分人；未记录每一次上手，无法自动推断实际上一位击球失败者。
- 犯规付给下家 1 分，提示自由球，不结束本局。
- 普胜／小金后由赢家的座位下家开球；大金／黄金9默认赢家续开，开关关闭后改为赢家下家开球。按本次用户给出的具体示例实现，不标作全国统一规则。
- 整笔撤销恢复分数、局数、开球人和本次操作后的击球人。
- 让杆是示例内的非计分记录，不自动判断真实规则的让杆资格。
- Demo 中的旧版规则标识用于展示历史记录样式；原生三端现已按同一规则实现，旧数据不迁移、不重算，详见 [原生契约与验收](../../nine-ball-14710-native-contract-2026-10-24.md)。
- 编辑比分会校验全员合计为 0，支持整笔撤销；不会把手工更正计入事件次数。

本轮已检查手机宽／窄容器、长姓名、四位正负比分，以及普通／小窗口圆表。手表按现有原生结构不展示手机的分项统计条。`verification.json` 记录本轮验证，`phone-left-cue-v4.jpg` 为最终手机预览；V2/V3 截图保留早期迭代。Demo 默认两人，仍可切换 2/3/4 人。

源文件：`source.html`（界面）、`rules.mjs`（纯规则）。

```sh
node build.mjs
node --test rules.test.mjs
```

`build.mjs` 把规则内联到 `index.html`，避免直接打开本地文件时的模块跨域限制。
