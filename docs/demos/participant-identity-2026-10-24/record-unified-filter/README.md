# 记录页：合并分类与筛选

日期：2026-10-24。按最新讨论更新原记录页 Demo，沿用此前外观与示例数据，展示 iOS、Android、320px 窄屏和筛选空结果四个可交互场景。仅 HTML 演示，未修改原生业务代码。

## 当前方案

- 移除常驻的“全部 / 计分 / 计时”，也不增加顶部分类下拉或独立筛选图标。
- 沿用“更多 → 筛选”，统一包含记录类型、时间、项目。编辑、清空保留在更多菜单。
- iOS 标题居中，Android 标题靠左，右侧只展示搜索与更多的示意位置。原生系统搜索继续由各端系统能力呈现。
- 正文第一项为“我的参赛”，进入二级页面后隐藏 Tab bar，返回记录后恢复。
- 未筛选时不显示状态行。筛选生效后，复用列表标题位置：左侧显示当前条件并可点击修改，右侧为独立的“清除筛选”。右侧不收缩，左侧按剩余宽度排布，条件过长可换行。更多按钮不再叠加绿点，避免重复提示。
- 清除筛选直接重置记录类型、时间和项目，保留搜索词与原始记录。筛选行随即隐藏，列表恢复为对应搜索范围的记录。
- 筛选为空时，筛选行继续显示，下方呈现“没有符合筛选条件的记录”及恢复按钮，不生成空白记录项。搜索与筛选同时为空结果时明确提示两种条件，并分别提供清除操作；仅搜索为空结果时只提供清除搜索。
- 筛选用草稿编辑，应用后生效；取消或关闭不改变已应用条件。重置也需要应用。
- 项目候选随记录类型变化，切换类型时清掉不适用的项目条件。
- 我的参赛是独立个人视图，仅含已识别本人身份的计分比赛，使用自己的时间与项目条件，不继承记录页的计时筛选。返回记录后保留原来的条件和搜索。

## 交互与验证

- 浏览器实点：“更多 → 筛选”中选择“计时＋本月”，应用后只显示一条计时记录及简短条件摘要。
- 浏览器实点：重新进入筛选，重置后取消，原已应用条件与一条结果保留。
- 浏览器实点：从计时结果进入我的参赛，仍展示两场本人比赛与统计，Tab bar 隐藏；搜索“小杨”得到一场比赛及对应统计，返回恢复原记录筛选和 Tab bar。
- 浏览器实点：Android 标题为左对齐，右侧只有搜索、更多两个按钮，没有独立分类入口；iOS 标题居中。
- 本轮浏览器实测：375px 与 320px 场景的筛选状态行均为 44px。320px 下“计时 · 本月 · 自定义计时”和完整的“清除筛选”互不重叠，两侧间距 8px，无横向溢出；条件左侧可收缩和换行。
- 本轮浏览器实点：清除筛选后恢复 4 条示例记录，状态行消失，普通列表标题高度恢复为 23px。叠加“小杨”搜索后清除筛选，搜索词仍在，显示 1 条对应比赛。
- 空结果场景实测：0 条记录，空状态位于筛选行下方，左右按钮不重叠、无菜单绿点。
- 脚本语法检查通过。所有编辑和删除仅作用于各平台示例状态，原始示例数据不变。

`source.html` 为可编辑片段，`index.html` 为可独立打开的预览。前一轮 `../record-tab-options/` 的四版作为探索存档；本目录是当前讨论采用的合并筛选方案。
