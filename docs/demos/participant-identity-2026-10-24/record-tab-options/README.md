# 记录 Tab 布局候选

日期：2026-10-24。状态：早期四个布局候选存档。后续已按讨论改为合并分类与现有筛选，最新可交互方案见 `../record-unified-filter/`；尚未改动原生业务代码。

## 当前代码确认

- `RecordsTab` 使用居中的 inline 导航标题“记录”。
- 顶部当前常驻“全部 / 计分 / 计时”三个 Chip。
- 已接入 `systemSearchable`，底层使用系统 `.searchable`，代码未指定固定的搜索按钮位置。右侧另有更多菜单，包含筛选、编辑、清空记录。
- 四个候选都在右侧给搜索和更多保留独立空间，以比较分类与个人入口的布局；原生实现时仍需核对系统搜索最终呈现。

## 四个候选

| 名称 | 分类位置 | 我的参赛位置 | 主要取舍 |
| --- | --- | --- | --- |
| 左上分类 | 左上角“全部”下拉，标题继续居中 | 正文第一行独立入口 | 对当前结构改动较小，入口容易发现；多一行导航入口 |
| 标题下拉 | 居中标题同时显示当前记录视图并下拉 | 同一菜单中的“个人”分组 | 最省正文空间；个人入口隐藏较深，需点标题 |
| 左题右筛选 | 标题靠左，右侧依次为类型、搜索、更多 | 正文第一行独立入口 | 两侧职责清楚；右侧按钮较多，需要变更当前标题对齐 |
| 独立切换 | “全部记录”模式的类型收进左上角 | 正文双向切换“全部记录 / 我的参赛” | 两种任务都容易发现和切换；保留一行一级切换控件 |

早期曾建议优先评估“左上分类”。核对现有更多菜单中的时间/项目筛选后，已改为只保留同一个筛选入口，并在其中加入记录类型。四个候选保留供回看，不代表当前推荐。

“全部 / 计分 / 计时”是记录类型；“我的参赛”是个人参赛视图，不作为第四个同类 Chip。个人视图只包含已明确身份的计分比赛，不包含计时记录。

二级页面不显示 Tab bar：“左上分类”和“左题右筛选”进入我的参赛详情后隐藏，返回记录根页后恢复。“标题下拉”和“独立切换”是在记录根页切换视图，因此保留 Tab bar。Android 遵循原有左对齐标题，可采用右侧分类按钮；不为套用 iOS 候选而强制居中。

## 演示范围

- 使用同一组虚构记录比较四种布局。
- 可以切换分类、进入本人视图、返回、搜索名称或项目。
- 右侧更多菜单的筛选、编辑和清空仅作用于各候选的演示数据，各候选状态互不影响。
- 四个版本通过对话内方案轮播切换，每个版本保留自己的交互状态。
- 暂不变更名称关联、三个名额、本人身份判重等已经讨论的规则。

`source.html` 为可编辑交互源，`index.html` 为独立预览包装。主流程原有的 `../source.html` 保留，选定后再整合。
