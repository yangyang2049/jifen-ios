比赛结束时刻:现状分析与分享转化重设计

结束弹窗是用户情绪峰值最高的一刻——赢了想晒,输了想约下一场。现状的「分享」却把这一刻浪费了: 分享出去的是一张带着弹窗和按钮的屏幕截图,文案没有品牌署名。下面的 demo 左侧是现状的像素级复刻(含"分享出去的图"实况预览), 右侧是建议的新方案(可点击「分享战绩卡」体验完整链路)。

P0 · 分享物质量

分享出去的图 = 带弹窗的截屏

点「分享」那一刻结束弹窗还在屏上,ScoreboardShareSupport.present 直接截取整个 keyWindow—— 发出去的图带着黑色蒙层、「再来一场 / 退出」按钮,像一张 bug 截图。这是分享最致命的质量问题。

P0 · 零品牌归因

分享文案没有 App 署名

文案只有一行 "红队 21 - 18 蓝队":无 App 名、无链接、无运动类型、无时间。 收到的人不知道这是什么 App 产出的,裂变链路完全断裂。记录详情页的分享卡其实已经有品牌页脚 + 下载二维码,却藏在二级页面。

P1 · 入口权重

分享与「退出」平级

「查看记录 / 分享 / 退出」三个等宽灰按钮并排,分享是增长杠杆,视觉优先级却排第四; 唯一的高亮主按钮给了「再来一场」(留存动作)。两者可以并存,但分享值得更高的视觉权重。

P1 · 情绪与细节

结果区没有"值得晒"的内容

弹窗只有一行大比分:无胜者庆祝(皇冠/奖杯)、无网球逐盘比分(6-4 / 3-6 / 7-5)、无时长日期。 赢球的炫耀欲没有被视觉放大,比分之外的"故事感"全丢了。

落地路径建议

按投入从小到大分三档,A 档几乎零风险,可先行上线看数据
A · 止血(1–2 天)

先把分享物质量修对

  • 分享改走 ImageRenderer 渲染分享卡,替换 captureKeyWindowImage;截图方案兜底时先隐藏弹窗再截纯计分板
  • 文案模板:"🎾 网球 · 蓝队 2:1 红队(6-4, 3-6, 4-6)· 用 iScore 记录 jifenqi.com/download"
  • 复用现成组件:RecordDetailShareCardView + ShareQRCodeRenderer(品牌页脚 + 二维码已实现)
B · 重设计(本 demo)

结束弹窗 = 战绩卡时刻

  • 胜者庆祝行(👑 获胜 / 平局对应文案),多人均分场景兼容 multiParticipantGrid
  • 比分下方增加逐盘/逐节 chips 与时长日期 chips(数据源:ScoreboardRecord / 实时 state)
  • 双 CTA:分享战绩卡(主)+ 再来一场(次);查看记录 / 退出降为底部文字链接,44pt 触控热区保留
C · 增长放大(后续)

让分享有理由、有闭环

  • 里程碑文案:本周第 3 胜 / 连胜 2 场 / 双方对战 10 场(数据都在记录库里)
  • 败方视角战报:"惜败 4-6,约再战"——输的人也需要分享理由
  • 埋点已有 trackSuccessfulShare,按 A/B 分版对比分享率与二维码扫码归因
现状实现参考:jifen/Features/Scoreboard/Shared/GameOverDialog.swift(弹窗与 ScoreboardShareSupport)、 ScreenshotSaveCoordinator.swift(截图管线)、 jifen/Features/Records/ScoreboardRecordDetailPage.swift:1151(已有的品牌分享卡基建,含虚线分隔 + App 图标 + 下载二维码页脚,1:1 对齐安卓)。 注意:分享卡在结束时刻生成需先持久化记录(Tennis 当前在退出/查看记录时才 persistSnapshot),或直接用实时 state 构建卡片内容。
