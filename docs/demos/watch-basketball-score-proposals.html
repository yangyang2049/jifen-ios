Apple Watch 篮球记分 · 最终方案

圆角矩形表盘（45mm 396 × 484）。一块屏只放三件事：左红右蓝两块色片 = 两队， 色片顶端 = 比分，点它就是 ＋1，下面两条 = 2 分 / 3 分。 竖向按 40% / 30% / 30% 分配：分数区最大，2 和 3 是两条不需要瞄准的带子。 记一次分永远是一下点击；记错就长按同一位置减分，或点中间那枚 ↺ 撤销。 文件末尾附了圆表 466 × 466（华为 / Wear OS）的适配：同一套逻辑，换个摆法。

分值档位

可以直接点：点分数 = ＋1，点下面 = ＋2 / ＋3，长按同一位置 = 减去该分值，中间 ↺ 撤一笔。红队是主队（左），蓝队是客队（右）。

最终版

分数即 ＋1，下面两层是 2 分和 3 分

罚球是最常按的一档，所以它占了最大、最靠上的那块面；2 分和 3 分各占下面 30%，闭着眼也不会按错。

  • ＋1 命中面 99 × 88 pt，2 / 3 各 99 × 66 pt，都远超 44 pt 建议。
  • ＋1 只是分数正下方的两个灰字（10 pt / 白 60%），不占横向宽度，也不抢点击；三位数比分照样能占满半屏。
  • 2 分上方那条分隔线比 2 / 3 之间更重（白 32% vs 16%）——它负责把「点分数＝1」和「点下面＝2/3」分开。
  • 撤销 20 pt 圆点骑在两个比分的中线上，不占独立一行；顶栏只放节次和单节剩余，右侧让开系统时钟。

R1 · 直接套用原方案色片铺满整圆，内容按同一套比例排。
比分、2 分都还在，但最下面那条 3 分被圆弧切掉两个外角，视觉上变成月牙；最底部的可点面积只剩中间一段。
R2 · 圆表适配比分并排挪到圆心上方（最宽处），＋1 在各自比分里；2 / 3 改成 2 × 2 网格，行 = 分值、列 = 队。
四个格子都在圆心附近，不被弧线切。
为什么不能照搬：原方案靠「上 1 / 中 2 / 下 3」的竖直顺序，可圆表的顶部和底部都是窄弧。3 分那条越往下越窄，屏幕最底端宽度收成 0，实际可点区域只有矩形的一半左右。
R1 的实测：2 分 / 3 分各 116 × 60 dp；3 分的外下角超出圆弧 46 dp，比分块的上外角超出 33 dp——两处都会被圆直接切掉。
R2 的实测：比分块 68 × 63 dp、数字 37 dp；2 / 3 每格 107 × 59 dp，四边全部落在圆内（外角最多贴到弧线 1.5 dp，被圆角吃掉，看不见）。

落地要点对应当前 watch 工程

  • 入口：WatchHomeTabView.swift 的 WatchHomeItem 现在有意不含 basketball（只有手机发起的联动能开历史板）；加回来时把「本机开赛」和「手机联动」两条路径分开。
  • 动作码：＋1 / ＋2 / ＋3 都落一条 WatchScoreAction，operationCode 复用手机在发的 basketball_score_1|2|3（BasketballSessionStore.swift:389）；长按减分用同码 scoreChange 负值，撤销沿用 undoCheckpoints。
  • 分数区是按钮：整块（队名 + 比分 + ＋1 浮字）用 .contentShape(Rectangle())，按下时整块泛白约 80 ms；浮字加 .allowsHitTesting(false)，别让它挖出死区。
  • 首次提示只做一次：第一次进表盘时分数区呼吸高亮 1.5 s、＋1 上浮一次，之后永不再现——这是整套设计里唯一的「需要解释」的地方。
  • 三人篮球：只有 ＋1 和 ＋2，下面只剩一层、自动撑满，布局不换。
