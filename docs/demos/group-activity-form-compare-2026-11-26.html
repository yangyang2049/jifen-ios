#位置iOS 现状安卓 / 鸿蒙1:1 照抄要改什么
1活动名称标签「活动名称（选填）」独占一行在框外；下面再挂一行自动命名说明placeholder 就在填充块里；自动命名说明收进行尾「?」气泡去掉外层 label 与常驻说明行，改用 placeholder + 复用 iOS 已有 popover 帮助（CustomDialogs.swift:62-89）
2玩法（单打 / 双打）排在日期、报名截止、地点之后（第 5 屏位）紧跟名称下方，第一眼就能选行序调整，同时挪 onChange(of: format) 的人数联动位置
3日期 / 开始时间半宽并排两个系统 DatePicker 字段（窄屏 ViewThatFits 才转竖排）两个整行填充块，行首图标 + 行尾箭头换成自绘行 + 底部弹层选择器
4报名截止时间独立标签 + 系统字段；「恢复为活动开始时」另起一行一行三段「图标 + 标签 + 值右对齐 + 箭头」，恢复按钮内联在下一行合并成单行三段布局，值右对齐
5地点标签 + 输入框 + 行尾小箭头（打开常用地点）整行块 + 行首地点图标 + 行尾箭头加行首图标，去掉标签行
6报名人数标签 + 系统 Stepper（− 8 ＋）；多人比赛说明常驻一行单行「报名人数 …… 8 ?」，说明进气泡Stepper 换行内数值 + 气泡；说明从常驻行移进气泡
7备注标签 + 多行描边输入框填充块，placeholder 当标签同 1
8分组容器每个字段一张白色圆角卡片 + 卡片间距没有卡片，所有行直接在灰底上等距排列去掉 .group 容器与卡片描边，统一 12pt 行距
结论：差别只有两类 —— ①字段名放哪（iOS 在框外独占一行；两端放进框内当 placeholder，说明收进行尾问号气泡）；②行长什么样（iOS 是「标签 + 描边输入框 + 白卡片」；两端是 48 高填充块 + 行首图标 + 行尾箭头，且不分组）。 字段集合、校验规则、文案、提交接口完全一致，所以 1:1 照抄是纯视觉改造，不动业务逻辑。
照抄必须同时补两件事，否则是净退步：① 填了内容后字段名不可见 → 每行补 accessibilityLabel（安卓靠 .semantics{ contentDescription }，见 GroupActivityForm.kt:133）；② 表单从系统 Form 变成自绘滚动容器后，键盘避让、scrollDismissesKeyboard、iPad 宽度上限都要自己接管。
