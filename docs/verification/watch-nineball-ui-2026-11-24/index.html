6 条

P2「选择人数」弹层里「4 人」按钮超出卡片底部，点下缘会把弹层关掉
  • 无障碍树里 Button '4 人' 的 frame 是 {{28,180},{152,68}}（pt），即按钮从 180pt 一直延到 248pt 屏幕底；而卡片背景在 233.5pt 处收边（截图 3p_02 中间列像素扫描：y≈467px 之后已回到遮罩色）。
  • UI 测试第一版按元素中心 tap() 时直接失败——弹层被遮罩关掉、停在首页；改成点按钮上部坐标后才稳定进入设置页。
  • 建议：三个选项放进等分高度或可滚动容器，卡片底部留 8–10pt 内边距，别让最后一行压到卡片圆角外。
P2九球 3/4 人设置页首屏看不到第 3（4）名选手的名称行
  • 设置页 ScrollView 行高 52pt，行起点 112 / 164 / 216pt，而「开始」按钮悬浮在 188–248pt，正好把第 3 行整块盖住：截图 3p_03_setup 首屏只有选手 1、2 与绿色「开始」；向上滚动后才露出选手 3（3p_03b_setup_scrolled）。
  • 4 人局同理（4p_00_setup / 4p_00b_setup_scrolled）：首屏只能看到前两行。
  • 影响：开 3/4 人局时第一眼以为只有 2 个名字框，需要额外一次滚动才发现还要填第 3、4 人。
  • 建议：名称行改紧凑（行高 44pt 或折叠成「选手」入口），或让「开始」只占内容高度、不覆盖最后一行。
P34 人棋盘下球杆徽标偏小，辨识度低于 2 人布局
  • 徽标白色笔画实测 bbox：4 人布局 16×16px（≈8×8pt），2 人布局 20×20px（≈10×10pt）。
  • 3 人布局里 OCR 会把徽标和姓名连读成「／ 选手1」（3p_04），说明笔画已经细到接近文字噪点级别。
  • 建议：4 人布局下徽标不小于 10pt，或在比分下方补一条「开球」文字标签。
P3事件面板标题里「开球」胶囊与姓名几乎贴在一起
  • 3p_16 的 OCR 把标题读成一整串「● 选手2开球」，说明 4pt 的间距在 9pt 胶囊下视觉上粘连。
  • 建议：间距提到 6–8pt，或加一个分隔点。
P3普通胜 / 小金 结算后开球人自动轮转，界面没有任何提示
  • 3p_07 得分后球杆徽标已经从选手 1 跑到选手 2，3p_09 的开球人面板对勾也落在选手 2（规则见 ScoreCore/NineBallChaseTransfers.swift:73-77：普通胜/小金结束后 breaker 轮到下家，大金/金九保留）。
  • 但计分板上没有任何「开球人已轮转」的反馈，用户容易以为徽标在乱跳。
  • 建议：结算后 toast 一句「开球人 → 选手 2」，或在开球人面板标题补「本局 · 第 N 局」。
观察2 人单人付分时开球人的「小金」直接置灰，没有任何文字解释
  • 截图 2p_02：小金格子区域最大亮度 73（禁用）；2p_03 同一位置最大亮度 255（可用），置灰确实生效。
  • 与手机端行为一致，属于预期；但手表屏幕小，建议禁用时补一句「小金需非开球人」或在 2 人单人付分下直接隐藏该按钮。

场景 A · 3 人局（主流程）

从首页进入九球 3 人局：开球人徽标 → 事件面板 → 普通胜/小金/让杆的一步式选人 → 长按菜单切换开球人 → 大金直出 → 完赛遮罩。

场景 B · 4 人局（2×2 棋盘）

4 人棋盘布局下的同一套规则：一步式付分人、开球人切换、小金推荐「开球」。

场景 C · 2 人局（对齐手机端的小金置灰）

2 人单人付分时，开球人的「小金」置灰；非开球人小金直接出分，不弹二级选人。
