## 最终覆盖结果

2026-10-20 本轮最终采集为 **64/64 段自动化流程通过，1,004 张检查点截图**。展开内屏与合拢外屏各 32 段、502 张；内屏原始录像约 71.95 分钟，外屏约 66.10 分钟，合计约 138.05 分钟。单独筛选一种屏幕后，8 倍速连续浏览约需 8–9 分钟，另加按需暂停时间。

29 个项目均保存设置、计分板、菜单及记录详情；具有样式入口的 28 个项目也均保存样式面板。投篮训练没有该入口，覆盖清单保留“—”。二三级范围按下表与每章检查点核对；截图含弹窗、滚动和编辑状态，不是 1,004 个独立页面。

旧失败尝试保留在原采集目录 `attempts/`，不计入最终通过统计，也不复制到交付版索引。最终方向匹配缓存无低置信提示。最终文件校验为 0 个问题（PNG/JSON、像素尺寸、视频可读性、时间点、屏幕一致性、红黄牌边缘及完整目录覆盖）；结果见交付目录的 `validation.json`，项目覆盖表为 `catalog-coverage.csv`。这项文件校验不替代视觉与功能验收。

## 采集方式

- 原生 iPhone Duo / iOS 27.1 模拟器，设备 `57F91B1F-92B7-4948-90FE-936BBE191802`。
- 展开内屏使用上述设备；外屏使用独立设备 `0037099A-5490-4EA3-8ACE-CEB00776C6C8`（Jifen Duo folded walkthrough 20261020）。两台设备分别固定姿态录制，由 Device Hub 控制，不向产品添加设备方向判断。
- MP4 是模拟器真实连续录屏，无音频；包括加载、滚动、弹窗、返回和应用重启。
- 显式指定模拟器 display UUID 采集实际内外屏像素，避免 XCTest 内屏黑图或默认采到非活动外屏。
- UI 测试通过本机文件握手通知宿主截图；同一时间点写入 PNG、界面层级和视频秒数。最终重录在截图后保留约 0.8 秒稳定画面再继续导航，避免视频时间点落入紧随其后的重启画面。
- 每段保存应用与 UI 测试可执行文件的 SHA256、xcodebuild 日志、xcresult 路径和起止时间。
- 失败、中断或复核发现缺页的章节单独标出。没有检查点的空测试即使 xcodebuild 返回 0 也算失败。

## 本轮发现与修复

倒计时原先将 `phone && width > height` 等同于高度紧张，展开内屏会隐藏预设、模式切换和唯一的自定义编辑入口。现改为按实际可用高度是否小于 500pt 缩减控件；展开宽窗口保留预设与自定义入口。没有调整全局旋转策略。

倒计时自定义弹窗首次打开时曾显示旧的 0:30，虽然底层已经选择 5:00；将字段同步移至弹窗显示时，并直接断言初始字段为 5:00，再验证修改、运行、暂停、恢复、复位。

红黄牌在展开内屏右侧与底部曾留下白边；补充当前牌色的全窗口背景。AA、积分榜、弹幕与预约加入键盘“完成”操作，并支持拖动收起键盘，保留输入后访问下方按钮的路径。弹幕运行中的编辑面板也按实际安全区避让系统状态区，并保留键盘避让，避免输入框右端伸入控制中心触控区域。外屏的长滚动弹幕还曾以文字自身宽度撑大容器，将返回/编辑按钮挤到屏幕外；现将文字裁切在实际显示宽度内，录制断言同时检查三个按钮完整位于窗口内。

UNO 与多人计分板的边缘玩家名、四种棋钟角落角色标识，原先会与展开内屏的系统时间/无线状态胶囊重叠；现按当前视图的安全区避让，保留全幅背景。九球（目录中的“追分”）底部统计格曾与浮动返回/菜单重叠，现为底行统计格预留按钮高度。上述修改均未增加方向判断或改变方向锁策略。

篮球与 3×3 外屏原先将单侧安全区同时作为两侧字号留白扣除，导致左队比分和队名明显缩小。现按按钮列、单侧安全区和实际留白计算独立名称/比分区域，两侧采用共同的最紧宽度，保留用户字体与倍率；增加 3 项布局回归断言。毽球团体赛样式预览为顶部退出/确认按钮留出空间，避免覆盖第一行成员名。

小组比赛记录卡片补充完整矩形点击区域，避免卡片中央留白无法点入比赛详情。排阵表单清空座位后，旧名单快照曾继续显示原成员姓名；现仅在当前成员 ID 与快照一致时使用旧姓名，空位立即显示选择成员。录制断言覆盖移除及恢复本地座位，不提交排阵。

录制脚本也发现过两类假覆盖并补正：外观弹窗未关闭导致 FAQ 点击失效；宽首页没有窄屏“全部工具”箭头。对应测试增加目的页断言并修正入口。排阵点选还会先确认目标完全离开固定保存栏，避免 XCTest 对被遮挡项的 `isHittable` 假阳性。失败尝试不计入有效页面遍历。记录列表的射箭、简单计分和多人计分使用 canonical ID，测试入口统一做显式映射，避免用目录 ID 找不到真实记录行。昵称编辑截图必须等软件键盘真实出现才采集。内屏的计分设置本来就能一屏显示全部选项，重复滚动图是同一页面状态，不能算作更多页面。长预约表单使用实际滚动容器坐标，并断言提醒控件真实可见且关闭，才保存本地样例。外屏原生表单滚动时会收起导航操作，保存/关闭前先滚回表单顶部并检查按钮可见，避免把收起状态误判为不存在。

小组样例模式还补齐了详情页的只读传输：仅 Debug 且显式带 `-UITestGroupsFixture` 时生效，从进程内样例缓存读取；未知路径、非空游标和全部写操作直接本地失败。成员战绩、比赛详情和报名页增加样例内容及无加载错误断言，避免只有导航标题正确而内容实际失败。活动编辑和排阵下部的真实入口也独立记录。
